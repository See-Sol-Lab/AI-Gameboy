# 口袋跑团

两位玩家一起处理世界中的危机。支持AI对AI、人类对AI。需要人类在仓库根目录的 `data/narrator.json` 自行配置荷官Key。

2.0把原剧本、可改变的节点和玩家实际改写的世界分开。原剧本是“没有玩家时会怎样”的悲剧参照；每幕荷官承接当前固定状态、真实成果和玩家已经改变的世界。

- 主线只有三个预写阶段；进度显示完成阶段数。完整成功完成一阶段；两次部分成功也能完成，未完成时保留进展。
- NPC与两位已选身份各有两条旧事，共六条。每条只预写两份证据与它们支持的简短答案。调查成功得到两份证据，部分成功得到一份。选择“推断”写结论与依据，意思吻合才揭示旧事；推断不额外掷骰。
- 大多数行动用节点指定的智慧、体力或幸运加六面骰，再算身份、物品和同伴支援修正。
- 主线奖励物品直接记录为队伍所有；NPC位置只有预写节点成功才迁移。第八幕后NPC不再提供新线索，已有证据仍能用于推断。
- 双人先选本幕目标，再自由发挥做法。主线、公共事件和NPC调查的目标占用会显示，帮助队友避免无意重复；行动正文和个人旧事调查仍各自暗投。
- 危机未解除时每幕危险自然+1，失败另有代价；主线完成后停止自然加压。没有与故事钟声混用的0–8时钟。可以继续调查、开店、种田、修行，成功发挥写入世界变化，后续荷官必须承接。
- 主线与六条旧事全部完成且未触发BE，提前HE；第十幕仍有欠缺则TE；危险满格或无人生还则BE。TE也可以是世界获救、部分个人谜题未解，不能强行写回原悲剧。
- 第十幕调查成功拿齐两条证据时，可在同一行动中明确提出推断，荷官在结局结算前核对。结论与证据及答案吻合才揭示旧事；单纯获得线索、提问或乱猜不算完成。
- 收尾行动的决定直接交给荷官承接结局，写入本幕结果与报告；它不额外掷骰，不自动获得物品或完成旧事。NPC退场后从荷官现场资料中移除，仍可引用已取得的记录，结局可交代其后日生活。
- 最终结局保留历幕收尾原文中的独有决定，尚未选择的去留保持开放；并根据实际成果交代关键道具的使用、合核或安置轨迹。背包保留已获物品记录，不额外引入消耗或合成规则。
- 仅提供当前2.0规则和界面。《口袋穿越》使用自己的合同。

维护者：规则在 `rules.py`，界面在 `ui.js`，纯数据荷官合同在 `console/tabletop_contract.py`，API由 `console/narrator.py` 调用。每次API调用独立，提示按通过条件、已确认世界、本轮行动组织；引擎提供JSON模板，预填席位、行动引文、变化条数、地点和可用对象，荷官只核对推断并填写变化、场景或结局文字。当前任务只保留上一次校验错误，人工重召时附上明确修正要求，成功后不带入下一任务。每幕数值先入账，交稿失败可人工重召，数值结算不重复执行。

玩家从掌机卡带架插卡、复制席位信息给AI即可；不必阅读 `rules.py`。完整操作见[使用教程](../../给AI的使用教程.md)。卡带清单在 `manifest.json`，仅保留当前规则。存档、Key和运行日志不要随卡分享。
