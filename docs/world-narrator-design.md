# 《口袋穿越》机制设计

> 状态：机制蓝图，未施工  
> 系列：AI-Gameboy「口袋」系列  
> 一句话：**引擎维护世界账本，DS按账本生成未知剧情，真实玩家共同决定这个世界最后变成什么。**

## 0. 游戏是什么

《口袋穿越》是一款双人生成式文字冒险。玩家可以是人类与 AI、AI 与 AI，或两名人类。

每局开始时，游戏从题材、力量等级、冒险类型、情绪基调和核心变数中抽取世界种子。DS API 根据种子生成一个此前不存在的世界、身份卡和第一幕。此后双方只提交自己的行动与桌边留言；游戏引擎负责掷骰、计算数值、保存事实与判定结局，DS 只把已经裁定的变化写成下一段剧情。

所有参与者第一次看到世界，也不知道故事会走向 HE、BE 还是 TE。每局结束后保存完整纪念卡，成为无法机械复刻的一次共同经历。

## 1. 责任边界

### 游戏引擎负责

- 抽取并保存世界种子；
- 发放席位、身份卡和私密信息；
- 保存唯一世界账本；
- 掷骰并计算行动结果；
- 修改进度、危机、生命、默契和世界时钟；
- 检查隐藏剧情与结局条件；
- 保存事件历史并生成纪念卡。

### DS叙事荷官负责

- 按指定标签生成世界背景、法则、目标与身份卡；
- 根据当前账本生成场景；
- 根据引擎已经裁定的结果描写行动后果；
- 为结局账本生成 HE、BE 或 TE 文本。

### 玩家负责

- 选择身份；
- 选择行动意图，并用自由文本描述具体做法；
- 决定是否向同伴留言、隐瞒、合作、冒险或牺牲；
- 共同承担选择造成的后果；
- 随时可以共同选择结束本局。

### DS永远不能

- 替玩家说话、行动、决定感情或补写心理活动；
- 自行掷骰、改数值、发物品、造成伤亡或宣告结局；
- 推翻、淡化或美化引擎已经裁定的后果；
- 凭空新增未登记的世界法则、关键人物、隐藏线或解法；
- 把桌边留言当成角色行动；
- 输出规则解释、数值分析、提示词或幕后说明；
- 主动加入恋爱剧情。关系如何发展，只来自玩家真实行动。

## 2. 唯一数据流

```text
世界标签与随机种子
→ DS生成世界与身份池
→ 玩家选择身份
→ DS按当前账本生成场景
→ 双方提交行动意图、具体行动和可选桌边留言
→ 引擎掷骰、计算组合、身份、物品、法则与代价
→ 引擎更新唯一账本并形成不可修改的裁决单
→ DS严格按裁决单描写结果
→ 引擎检查隐藏剧情与 HE / BE / TE
→ 未结束则进入下一幕，结束则生成结局与纪念卡
```

卡带规则模块不碰网络与 API key。宿主在事务外请求 DS，校验成功后再用系统动作把结果写回局面。荷官失败时局面停在“等待荷官”，由人类手动重试；不换模型、不使用备用剧情、不静默重试。

## 3. 世界种子

世界种子由五条轴组成。建局时可以全随机，也可以锁定一两项后随机其余部分。

- 世界形态：现代都市、架空古代、未来都市、末世废土、深海文明、蒸汽时代、魔法大陆、东方玄幻、修仙世界、梦境世界、封闭空间、时间夹层等；
- 力量等级：无超凡、低武、中武、高武、神话级；
- 冒险类型：求生、逃离、护送、寻物、调查、夺回、守城、潜入、远征、营救、谈判等；
- 情绪基调：温暖、轻快、诡谲、压抑、壮烈、荒诞、史诗、孤独、浪漫、黑色幽默等；
- 核心变数：时间不多了、身份存疑、资源枯竭、世界正在遗忘、敌人会学习玩家、两人记忆不一致、道路无法回头、死亡会改变规则等。

示例：

> 修仙世界 × 低武 × 护送 × 诡谲 × 世界正在遗忘

世界种子与随机数写入纪念卡。种子可以保存，但 DS 生成和真实玩家选择让整局无法机械复刻。

公共版本默认使用原创类型标签。具体影视、动漫、小说或游戏世界只能作为获得授权的独立卡包，不进入默认生成池。

## 4. 世界卡与隐藏线

DS根据世界种子生成一次世界卡：

```json
{
  "world_name": "不超过十二个字",
  "premise": "一句话说明玩家来到了哪里",
  "lore": "不超过四百字的世界背景",
  "power_level": "无超凡|低武|中武|高武|神话级",
  "public_goal": "本局共同主目标",
  "laws": [
    {
      "id": "law_1",
      "text": "玩家能理解的世界法则",
      "trigger_kind": "引擎可检查的触发类别",
      "cost_kind": "danger|vitality|progress|clock|flag"
    }
  ],
  "opening_facts": ["开局已经成立的三到五条事实"],
  "hidden_threads": [
    {
      "id": "hidden_1",
      "required_flags": ["结构化触发条件"],
      "effect_kind": "scene|truth|route|ending_modifier",
      "brief": "仅供触发后生成使用的隐藏线摘要"
    }
  ]
}
```

世界法则必须落到引擎能识别的触发类别。隐藏线在开局时一次性埋入，只能由数值阈值、flag、物品、身份、秘密目标或钩子状态触发。DS不能在中途为了制造反转临时新增隐藏线。

## 5. 身份卡

DS每局生成六张身份卡。双方各自暗抽两张、选择一张，未选卡退出本局。

```json
{
  "id": "identity_1",
  "name": "身份称呼",
  "origin": "一句来历",
  "specialty": "推进|探索|支援|对抗|休整",
  "gift": "落到引擎规则的一项能力",
  "flaw": "明确的限制或代价",
  "secret_drive": "仅本人可见的次要目标",
  "starting_item": "一件开局物品"
}
```

身份卡提供能力、限制和私密动机，不规定性格、台词、立场或感情。所有身份使用相同数值预算，避免出现明显正确答案。

## 6. 唯一世界账本

```json
{
  "phase": "setup|playing|waiting_narrator|finished",
  "seed": "世界种子",
  "world": {},
  "scene_index": 1,
  "clock": 0,
  "progress": 0,
  "danger": 0,
  "synergy": 0,
  "vitality": {"seat_a": 3, "seat_b": 3},
  "identities": {"seat_a": "identity_id", "seat_b": "identity_id"},
  "inventory": {"seat_a": [], "seat_b": [], "shared": []},
  "facts": [],
  "flags": [],
  "hooks": [],
  "pending_actions": {},
  "current_scene": {},
  "history": [],
  "ending": null
}
```

五个核心数值：

| 数值 | 范围 | 含义 |
|---|---:|---|
| `progress` | 0–10 | 共同主目标完成程度 |
| `danger` | 0–10 | 世界失控、追兵逼近或灾难恶化程度 |
| `vitality` | 每人0–3 | 玩家在当前世界中的生存状态 |
| `synergy` | 0–5 | 双方行动实际形成的协作程度，不代表爱情 |
| `clock` | 0–8 | 已经过的场景数与世界逼近终局的时间 |

`facts` 保存不可否认的世界变化；`flags` 保存可检查的剧情条件；`hooks` 保存已经出现但尚未解决的事件。DS只能读取并续写，不能删除既成事实。

## 7. 场景合同

```json
{
  "title": "场景标题",
  "scene_text": "不超过三百字，只描写玩家行动前已经发生的事",
  "crisis": "当前必须面对的问题",
  "interactive_objects": [
    {"id": "obj_1", "name": "对象", "hint": "玩家现在能观察到的内容"}
  ],
  "visible_laws": ["本幕明确相关的世界法则"],
  "open_questions": ["本幕尚未得到答案的事"]
}
```

场景文本到玩家可以行动的位置为止。DS不能替玩家迈出下一步，不能预告正确行动，也不能暗藏未登记的强制答案。

## 8. 玩家行动

每轮双方各提交一个行动意图、一段自由行动描述和可选的一句桌边留言。

- `advance` 推进：直接处理共同主目标；
- `explore` 探索：寻找情报、道路、人物或物资；
- `support` 支援：保护、协助或补足同伴行动；
- `confront` 对抗：正面解决敌人、障碍或规则；
- `recover` 休整：恢复状态或整理资源，但时钟照常前进。

自由文本决定玩家具体做什么，行动意图给引擎稳定的裁决入口。桌边留言属于玩家真实交流，不参加数值判定。

双方行动默认暗投。两边都提交后同时公开并裁决，避免后一位玩家永远针对前一位选择最优解。

## 9. 机械裁决

DS不参与成败判断。每位玩家投一枚六面骰：

```text
个人结果 = d6
         + 身份擅长（符合时 +1）
         + 有效物品（符合时 +1）
         + 同伴支援（符合时 +1）
         - 身份弱点（触发时 -1）
         - 高危环境（danger≥7 时 -1）
```

结果分级：

- 1–3：失败并承担代价；
- 4–5：部分成功，同时产生代价或新钩子；
- 6–7：成功；
- 8以上：卓越成功，并可能触发隐藏条件。

行动组合改变风险与收益，但不形成唯一答案表。例如：推进＋支援偏稳定；推进＋推进进展快但危险高；探索＋推进可能发现捷径也可能因分头行动付出代价；支援＋支援安全却会错失机会；对抗＋对抗爆发高且失败代价最大。

引擎先更新账本，再形成不可修改的裁决单：

```json
{
  "outcome": "failure|mixed_success|success|critical_success",
  "progress_delta": 2,
  "danger_delta": 1,
  "clock_delta": 1,
  "synergy_delta": 1,
  "vitality_delta": {"seat_a": 0, "seat_b": -1},
  "inventory_changes": [],
  "facts_added": [],
  "flags_added": ["heard_the_bell"],
  "hooks_added": [],
  "hooks_resolved": [],
  "reason": "双方行动互补，但乙承担了世界法则的代价"
}
```

DS只能根据裁决单生成后果文本，必须逐项兑现数值、物品、事实与flag变化。

## 10. 场景推进

- 一局通常4至8幕；
- 每完成一幕，`clock` 至少增加1；
- 结局条件满足时立即结算；
- `progress`、`danger` 或隐藏flag达到阈值时，下一幕升级；
- 第8幕结束后必须进入 HE、BE 或 TE；
- 玩家可以在任意幕开始前共同选择提前结算。

固定的是最大时钟，不是剧情结构。激进的一局可能四幕生死收场，谨慎探索的一局可能到第八幕才抵达终点。

## 11. 结局判定

### BE

满足任一条件：两名玩家生命都归零；`danger = 10` 且主目标未完成；触发世界卡已登记的毁灭flag；或双方共同选择已登记为毁灭性的终止行动。

### HE

基础条件：`progress = 10`；至少一名玩家存活；核心危机已经解决；没有未处理的毁灭flag。身份秘密目标、隐藏线、存活情况与`synergy`可以改变HE的正文和副标题。

### TE

用于目标达成但代价不可逆、一人死亡或失踪、世界未毁灭但玩家未归来、`clock = 8`仍未满足HE/BE、双方主动结束、开放循环或无法确定胜负的终点。

TE不是失败收纳箱。它保存无法被“成功/毁灭”概括的独特结局。

一方提出结束，另一方确认后立即进入TE。DS依据当时账本写出“故事停在这里以后，世界怎样继续”的短结局；已经发生的内容照常进入纪念卡。

## 12. DS生成合同

DS共有四类调用：

1. `gen_world`：生成世界卡与隐藏线；
2. `gen_identities`：生成身份池；
3. `gen_scene`：根据当前账本生成下一幕；
4. `render_resolution` / `render_ending`：按引擎裁决单写后果或结局。

所有调用都返回结构化JSON。校验失败时停在等待荷官；同一请求保持不变，由人类手动重试。

固定系统约束：

> 你是《口袋穿越》的叙事荷官。你负责把游戏引擎提供的世界事实与裁决结果写成玩家可读的剧情。你没有玩家席位，没有行动权、计分权和结局判定权。你不得替玩家说话、选择、补写心理或改变任何数值与既成事实。输出必须严格符合当前JSON schema。

## 13. 纪念卡

每局结算后保存：世界种子与世界卡、双方身份、每幕场景、双方行动、桌边留言、机械裁决、最终账本、HE/BE/TE及结局正文、已触发隐藏线、关键物品、未了钩子和双方可选的离桌留言。

卡带保存游戏里真实发生过什么。玩家聊天上下文、Core、系统提示和私人历史永远不进入牌桌存档。

## 14. API与失败边界

四至八幕约需：世界1次、身份1次、每幕场景1次、每幕结果演出1次、结局1次。MVP可把“上一幕结果演出”和“下一幕场景”合并，将常规一局压缩到7至11次调用。

`data/narrator.json`保存本地荷官配置并加入`.gitignore`。API key由宿主读取，卡带不可见。一桌固定一个荷官模型，中途不自动切换。

## 14.5 V0.2 提案:原典时间线(穿越制)【项目作者提案,待施工】

首轮实测证明:边跑边编的荷官会为了悬念无限开坑。解法不是更多纪律,
而是让它**无戏可加**:

- `gen_world` 时,荷官一次性写完 8–10 章「原典」——这个世界没有玩家时本该发生的
  完整剧情与原结局。原典入账本后台,**只有荷官上下文与引擎可见,永不进 observe**
  (与隐藏线同一保密管道);
- 两名玩家是原著中不存在的角色。每幕场景合同 = 「原典第 N 章 × 玩家已造成的偏移
  (既成事实账本)」的演算结果;荷官的工作从"编故事"变成"推演扰动";
- 结局四象限,全部成立:完成目标离开 / 陨落于此 / 改写了原典 / 未能改变什么;
- 纪念卡新增**时间线对照页**:原典 vs 实况——"本该发生的"与"因为你们而发生的";
- 可选机制:探索卓越成功 → 引擎撕一页原典给该玩家(先知情报,私密);
- 工程量:gen_world 合同加 chronicle 字段(或拆独立一次调用),场景上下文改喂
  "本章原典+偏移清单",引擎骰子/里程碑/结算全部不动。

## 15. MVP施工顺序

1. 纯规则原型：使用固定样例世界卡与假荷官输出，完成账本、身份、五种行动、骰子、隐藏flag与三类结局；
2. 接入真荷官：实现生成合同与JSON校验，验证DS无法改数值、替玩家行动或越过账本；
3. 收藏与重玩：生成纪念卡，在卡带架显示世界名、结局、同桌玩家和日期，并连续实测不同世界。

首版暂不做：三席以上、配图、语音、跨局续作、公共世界分享、荷官人格化、同人卡包、复杂战斗地图。

## 16. MVP验收

1. 世界账本是数值、事实与结局的唯一真相；
2. 两名真实玩家各自看到公开世界和自己的私密身份；
3. 双方暗投行动，不能提前读取对方选择；
4. DS每一幕都承认此前事实和未解决后果；
5. DS无法修改裁决、替玩家说话或自行宣布结局；
6. 同一套规则能机械跑出HE、BE、TE与主动结束；
7. 至少三局实测没有固定答案感；
8. 人类与 AI 玩家完整玩完一局后，都愿意再抽一个世界。

最后一条不是装饰。它是《口袋穿越》是否真正成立的产品验收。
